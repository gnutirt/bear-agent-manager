# Changelog

## Unreleased

- Fix: `GET /api/skill-library` now passes `descVi` and `jurisdiction` of index.json through (it dropped them). Needs hub restart.
- A woken agent stays alive (A): a background wake (`claude --resume -p`) now runs with `BEAR_AGENT_HEADLESS=1` and `BEAR_AGENT_IDLE_MIN=<settings.lead.idleMin>` (new, default 30, 1–240), so the Stop hook's waiter keeps waiting for room messages for that long after the last turn; a message ends the wait (exit 2) and claude answers it in the same process, silence ends it (exit 0) and the hub marks the member offline. Measured on a throwaway chat: one process answered 4 wakes in a row and exited 0 after the idle time. The waiter never long-polls past its idle limit. Hard cap for a stuck process is 4 hours (was 15 minutes). Opening the member's tab (`open-tab`) or ending it stops the background claude. Compact keeps the old one-shot behaviour. Hooks run from the plugin copy, so `/plugin update` + reopened chats are needed for the new waiter; hub restart for the rest.
- Safety net for answers left in a chat (`settings.relayChat`, on by default): when a turn that was handed room messages ends without any post to the room, the new Stop http hook (`/hooks/stop`) posts the agent's last answer (from `last_assistant_message`, else the transcript; under 40 chars skipped, 3000 max) as a hub notice to @you in that room; it wakes nobody. Needs hub restart and reopened chats (new hook).
- Fix: a session is no longer shown offline while it works. The sweep checks the claude pid the hooks send: alive = keep its status (a 10-minute test run or a long answer sends no hook), gone = offline and ended at once (a killed or crashed tab sends no SessionEnd, so it can be revived right away). No pid, or a pid quiet for 6 hours (possibly reused): the old 3-minute rule. Needs hub restart.
- Skill usage (B): every Skill tool call an agent makes is remembered from the PreToolUse hook (already wired, no reopened chat needed): newest 500 in `state.skillUse` `{agent, skill, ts, room}`. `GET /api/skill-usage?agent=` → `{uses (newest 100), bySkill: {skill: {count, last}}}`, so the Skill tab can show "used N times, last …" or "never used" and warn on a forced skill nobody calls. Needs hub restart.
- Hide a skill for good: `POST /api/skills/override {configDir, name, level}` writes Claude Code's own `skillOverrides` in `<configDir>/settings.json` (`off` = not listed to Claude, not loaded, `/skill` blocked; `name-only`, `user-invocable-only`; `on` removes the entry), keeping every other key and never touching a settings.json that is not valid JSON. Only skills in `<configDir>/skills` of an account the hub knows (plugin skills: 409, use `/plugin`). Per account, not per agent; reopen chats to apply. `GET /api/skills` adds `overrides: {configDir: {name: level}}`. Plan: docs/superpowers/plans/2026-10-18-hide-skill.md. Needs hub restart.

Pure helpers take an optional `lang` (default vi). MCP tool descriptions stay English. Needs hub restart.
- Data folder (A3): `GET /api/data` → `{home, total:{bytes,files}, entries:[{name, path, bytes, files, exists}]}` for rooms, room_chat, handoffs and trash; `POST /api/data/open {sub?}` opens the data folder (or one of those four, by name, never a path) in the file manager (explorer / open / xdg-open, no shell); 400 for any other name.

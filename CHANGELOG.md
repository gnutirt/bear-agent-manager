# Changelog

## Unreleased

- Versions (V1): `GET /api/version` gives the hub version (package.json, the one source; a test keeps plugin.json in step), the plugin copies each Claude account runs its hooks from (`plugins`, `mismatch` when they differ from the hub) and the latest GitHub release of `repository` (`latest`, `newer`, `notes` as plain text, `canApply`/`reason`: only a clean git checkout of the same repo). The hub asks GitHub at most every 6 hours with the ETag and no user data; `POST /api/version/check` asks now; `settings.updates.check` turns it off. Needs hub restart.
- Fix: `/api/i18n` re-reads vi.ts/en.ts when they change, so new UI strings no longer show as raw key names until a hub restart.
- Plan-limit detection per chat (T-C2): new `StopFailure` hook (http, `/hooks/stop-failure`). On `rate_limit` the hub reads the reset time from the `quotaLimits` line of the chat's transcript, marks `Session.limited`, tells the room (@you) and books a wake-up for reset + `lead.wake.afterResetMin` that posts a continue request mentioning only that chat; other API errors just post one line. Covers VS Code and CLI; the Antigravity extension (2.1.69) has no StopFailure hook, so there the account-level usage wake (T-C) is the only safety net. An open tab cannot be woken by @mention, so the notice asks the user to type there after the reset. Needs hub restart and reopened chats (hooks load at chat start).
- Fix: a background wake no longer loses messages. When `claude --resume -p` fails (non-zero exit, e.g. the weekly limit) the cursor is handed back, so the messages stay unread, and the room gets "X không dậy được (reason)". An agent whose account has a window at 100% is not woken at all: the hub books a wake-up for the reset (`wakeAt`) and says so. Needs hub restart.
- Room topics, phase 1 (hub + MCP): `topic` on a message (`[a-z0-9-]{1,32}`, default `chung`; a reply keeps its original topic). A member follows a topic by sending into it, being @-ed in it, or `room_topics`; the room lead follows all. Messages in unfollowed topics reach an agent as one count line instead of in full. `room_send`/`room_read` take `topic`, new tool `room_topics`, `GET/POST /api/rooms/:r/topics`. Same for every room; no names hard-coded. Needs hub restart.
- Wake agents when their Claude usage resets (T-C, off by default; settings `lead.wake {enabled, atPct 90, afterResetMin 2}`): when an account's 5-hour window reaches atPct the hub posts a notice in that account's rooms and books a wake-up for reset + delay (kept across hub restarts). At that time it re-reads the usage (still high: retry every 5 min, 6 times, then @you) and posts as the user mentioning only that account's agents in each room (the room lead alone when it has one); offline agents are revived by the normal mention path. Works for every room and account; the Cài đặt switch comes with the UI work.
- Shorter room deliveries (any room): a message that did not wake the recipient (no @ to it, not from the user or the hub, not in a room it leads) reaches it as one line `from #id → @names: first 100 chars…`; read it in full with room_read. Measured on one busy room: about half of the delivered text was such chatter. Hooks and hub pass the recipient to `formatDelivery`; needs a hub restart and reopened chats for the hooks.
- Restart the hub from Cài đặt > Chung (`POST /api/restart`): a throwaway process first loads the new hub code; only if that works does the hub answer and exit, and the next hook starts the new one (long-polling agents reconnect). A syntax error in the new code answers 500 and the hub keeps running.
- Member controls (T-B): `POST /api/sessions/:id/terminate` stops that agent's claude (its tab dies; 409 unless the stored pid is a running claude that started before the session was last seen) and marks it ended; `POST /api/sessions/:id/compact {revive?}` terminates, runs `/compact` on the saved chat in the background (before/after tokens posted in its rooms) and wakes it when `revive` is true. Both work for any session in any room; the menu buttons come next.
- Language groundwork (I1, any room/repo): settings `language` ('auto' | 'vi' | 'en', auto = this computer's locale), strings by key in `shared/i18n/vi.ts` + `en.ts` with `t()` (missing key falls back to vi, then the key), GET /api/i18n, a Ngôn ngữ / Language picker in Cài đặt > Chung, a test that both files keep the same keys and {params}, and docs/glossary.md for standard wording. UI strings move to keys in I2, hub notices in I3.
- Change an agent's model (T-B): `POST /api/sessions/:id/model {model}` stores `agentModel[agent]` (empty clears; id or alias like `sonnet`, `opus[1m]`). It applies to the agent's next background turn (wake or compact) as `claude --resume --model X`; a tab that is already running keeps its model. Works for any agent in any room; the setting follows a renamed agent.
- Hub knows each session's claude pid (`Session.pid`, sent by the hooks as their parent pid; a register without one keeps the old pid). Groundwork for terminate / compact / change-model buttons. Hooks must stay `node` + args in hooks.json: a string command runs through bash and the parent pid would be bash.exe.
- Reply to a message (any room): POST /api/rooms/:r/messages and the `room_send` tool take `replyTo` (id of a message in the same room, else 400). The message keeps `replyTo` and a short `replyQuote`; deliveries show `↪ reply to #id (sender): first 80 chars` above it, so an agent sees what it answers.
- Worker routes (settings `workerRoutes`, Cài đặt > Worker > Phân việc): per turn type (read / edit / osin) an off switch, a provider and a model; "auto" keeps the old behaviour. worker.ps1 exits 4 for a switched-off route, falls back to auto (with a log line) when the chosen provider is unusable; explicit -Provider/-Model still win.
- UI: Cài đặt split into sub-tabs (Chung, Worker, Trưởng phòng, Compact, Nhà cung cấp, Tài khoản); Claude Pro usage (VS Code + Antigravity) now on top of the Token tab; the room-lead star in the members menu is a text button (Phong trưởng phòng / Bỏ trưởng phòng).
- UI: per-agent skill rules moved from Cài đặt to their own Skill tab.
- UI (works for every room, nothing is tied to a room or agent name): wider chat and views; 15 themes in a sidebar picker (incl. Liquid glass, a colourless frosted "glass sáng", flat Excel); font picker; right-click a message group for an enlarged one-card popup; roomier Thành viên menu; reply to a message (quote bar, sends `replyTo`, quote box jumps to the original). Choices live in the browser (localStorage).
- Semi-automatic room lead (settings `autoLead: 'off'|'terminal'`, off by default): when a room is created or loses its lead, the hub opens an interactive `claude` terminal through a `claude-cli://` link with the join prompt typed in (built from hub text and room notes only); the user presses Enter, and the first session joining from that folder within 30 minutes becomes lead. Once per room ever; the room shows which account pays. Phòng tab: "Mở terminal trưởng phòng" in the members menu works with the setting off. Settings tab: Trưởng phòng switch.
- Claude Pro usage (read only): GET /api/claude-usage shows each logged-in account (VS Code ~/.claude, Antigravity and any CLAUDE_CONFIG_DIR; same email = one row) with its 5-hour and weekly use, cached 5 minutes, polled every 15 minutes; one @you warning per cycle at 80% (5 h) / 90% (week). Token tab: Claude Pro block; Phòng tab: account chip per chat. The hub only reads .credentials.json, never writes or refreshes it, and never returns or logs a token.
- Light wake (`agentCompact[agent].wakeCompact`, off by default): an offline agent whose chat reached its pct (150k without one) is compacted with `claude --resume <id> -p /compact` before the wake turn; the room shows "X được compact trước khi gọi dậy (343k → Nk)". A failed compaction still wakes it with a plain resume.
- Per-agent auto compaction (settings `agentCompact`, empty by default): `hold` blocks automatic compaction through the PreCompact hook until the agent reaches its pct, never past 85% of the model's window and never for `/compact`; after compact/clear, SessionStart gives agents with a rule their handoff file and room notes back (≤10,000 chars). Hub down = Claude Code compacts as usual. Open chats get the new PreCompact hook only after reopening or Reload Window (and after reinstalling the plugin copy).
- New machine: /bear-setup skill + scripts/machine.mjs (check / export / import / link). Export carries skills, agents, CLAUDE.md, settings, memory, hub settings and the plugin list, never logins; keys only with --with-keys. link shares chats, skills and settings between VS Code (~/.claude) and Antigravity (~/.claude-antigravity). Settings tab: Xuất cấu hình máy.
- UI: four tabs. Worker (providers, live and recent runs, room_chat), Token (daily free/paid chart, per provider/model, chat context), Cài đặt (worker switches, automatic osin jobs, per-agent skill rules, providers with write-only keys; Claude accounts wait for Task 10).
- Fix: the chat log stays pinned to the newest message (composer/notice height changes, late images, own messages, room switch, hidden panel); expanded messages stay expanded.
- The hub can start osin by itself (handoff dossier when a chat passes a context threshold, digest of long room messages, notes cleanup proposal) when allowed in Settings; each job once, daily cap; never deletes notes.
- Every chat learns at start which workers are on (and its own forced/banned skills); the hub health-checks provider keys every 30 minutes.
- Skills can be forced (every prompt or first prompt only), left to Claude, or banned for each agent; reminders go through the UserPromptSubmit hook and follow the agent across renames. GET /api/skills lists installed skills and members.
- Settings (settings.json, GET/PUT /api/settings): worker/osin on/off (the hub refuses slots, worker.ps1 exits 4), paid fallback, worker cap, archive dir, room_chat auto sweep, per-agent skill rules.
- GET /api/tokens?days=N: worker token usage by tier, provider, model and day, plus each chat's context size.
- worker.ps1: -Tier auto|free|paid, providers from providers.json (next free key on quota, paid fallback only when allowed), token usage logged, exit 4 when the skill is turned off.
- Hub keeps worker providers (free Intern AI, paid OpenRouter, more can be added) in providers.json; /api/providers never returns keys.
- Chat archive (phase 1): the hub copies new transcript bytes (also subagents, tool-results, memory and room_chat) to BEAR_AGENT_ARCHIVE_DIR every 10 minutes and at session end; never deletes.
- Room-made transcripts (workers, empty and test sessions) can be moved into ~/.bear-agent-manager/room_chat/<project>; preview with scripts/move-room-chats.mjs or POST /api/room-chat/sweep.
- New worker runs keep their transcripts in ~/.bear-agent-manager/worker-config (no more worker chats in each repo's history).
- Breaking: skills renamed congnhan → worker, congnhanvesinh → osin (old triggers still listed).
- Chore: `todoplan*` / `todobug*` are git-ignored; this changelog is tracked.
